# HiveMem guide: earlier release records

These dated records were moved verbatim out of [`public/guides/hivemem.md`](../../public/guides/hivemem.md) so that the published guide keeps only its current release record. They describe the guide as it was on each date: "above" and "below" refer to that version of the guide, and the versions they name are not current. For current instructions read the [published guide](https://hivemagnus.com/guides/hivemem.md); for what each release changed, read the HiveMem [changelog](https://github.com/ChefTaco/HiveMem/blob/main/CHANGELOG.md).

Release update, 2026-11-12: [Hive 3.3.0](https://github.com/ChefTaco/hive/releases/tag/v3.3.0) pins HiveMem 1.5.0, tag [`v1.5.0`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.5.0), commit `13281b0a0019484d2b639320207612c06ec8b26f`. Per its [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.5.0/CHANGELOG.md), it verifies Oathweave browser and service-account tokens with the suite's shared verifiers while keeping HiveMem's rules, and refuses at startup a service link issuer that is neither a lowercase native identifier nor an HTTPS URL. It adds `GET /health/live` and `GET /health/ready`, carries `x-request-id` on every response and in mutation audit receipts, and lets memory browse, search and stats filter by `agent_id`. Existing `/v1/health*` paths and unfiltered responses are unchanged. The standalone container example above keeps its original 1.3.1 review.

Release update, 2026-11-13: [Hive 3.7.0](https://github.com/ChefTaco/hive/releases/tag/v3.7.0) pins HiveMem 1.6.0, tag [`v1.6.0`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.6.0), commit `8948d16389194821e707fc31910e764e38443e8d`. The container example now matches the [README](https://github.com/ChefTaco/HiveMem/blob/v1.6.0/README.md) at that tag: the `1.6.0` image, the suite's `hive-qdrant:1.18.3-3` image, and no `HIVEMEM_TS_CORE_HOST` line, which the image now sets itself. It was not re-run with the new images. Per the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.6.0/CHANGELOG.md), 1.6.0 adds the suite audit export at `GET /v1/audit/export` for administrators and service tokens with `hivemem:audit:read`.

Release update, 2026-11-14: [Hive 3.8.0](https://github.com/ChefTaco/hive/releases/tag/v3.8.0) pins HiveMem 1.7.0, tag [`v1.7.0`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.7.0), commit `53b0c636cf81400926030601a89376a0b69e411d`. The container example now uses the `1.7.0` image, as the [README](https://github.com/ChefTaco/HiveMem/blob/v1.7.0/README.md) at that tag does, with the same `hive-qdrant:1.18.3-3` image; it was not re-run with the new image. The workspace rules above follow the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.7.0/CHANGELOG.md) at that tag, which also fixes a server stop caused by such agent IDs.

Release update, 2026-11-15: [Hive 3.9.3](https://github.com/ChefTaco/hive/releases/tag/v3.9.3) pins HiveMem 1.7.1, tag [`v1.7.1`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.7.1), commit `590a54722ce69269b40bd4ed53f14a20490603b7`. The container example now uses the `1.7.1` image, as the [README](https://github.com/ChefTaco/HiveMem/blob/v1.7.1/README.md) at that tag does, with the same `hive-qdrant:1.18.3-3` image; it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.7.1/CHANGELOG.md), 1.7.1 moves to `@hivemagnus/hive-common` 0.5.0, which also masks URL credentials with only a user or only a password in audit export details, and reads request bodies with the shared bounded reader: the rest of an upload over `HIVEMEM_MAX_BODY_BYTES` is discarded after the 413 instead of the connection being reset, and a client that disconnects mid-body gets a 400. Routes, responses and tokens are unchanged, and it adds no migration.

Release update, 2026-11-16: [Hive 3.11.0](https://github.com/ChefTaco/hive/releases/tag/v3.11.0) pins HiveMem 1.8.0, tag [`v1.8.0`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.8.0), commit `90552fd8a5e9c8242f68d8242bfb8e09b9262e6a`. The container example now uses the `1.8.0` image, as the [README](https://github.com/ChefTaco/HiveMem/blob/v1.8.0/README.md) at that tag does, with the same `hive-qdrant:1.18.3-3` image; it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.8.0/CHANGELOG.md), 1.8.0 adds the installer-only administrator provisioning endpoint described above. Hive's [UPGRADING](https://github.com/ChefTaco/hive/blob/v3.11.0/UPGRADING.md#suite-3110-guided-administrator-product-access) says an upgrade from 3.10.0 needs no migration flag.

Release update, 2026-11-17: [Hive 3.11.2](https://github.com/ChefTaco/hive/releases/tag/v3.11.2) pins HiveMem 1.8.1, tag [`v1.8.1`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.8.1), commit `816e414f4059c0ec3aecee3810a63029b702c87d`. The container example now uses the `1.8.1` image, as the [README](https://github.com/ChefTaco/HiveMem/blob/v1.8.1/README.md) at that tag does, with the same `hive-qdrant:1.18.3-3` image and `issue-token` example; it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.8.1/CHANGELOG.md), 1.8.1 is a fix release: `scripts/deploy_server.sh` no longer stages a model file or writes `HIVEMEM_CORS_ORIGINS`, which the server never read, the `hivemem-server --help` and `issue-token` error examples use `--subject emberpath` instead of the retired Hive Router, and the API reference documents the health report the server returns. It adds no migration.

Release update, 2026-11-17: [Hive 3.12.0](https://github.com/ChefTaco/hive/releases/tag/v3.12.0) pins HiveMem 1.9.0, tag [`v1.9.0`](https://github.com/ChefTaco/HiveMem/releases/tag/v1.9.0), commit `213a2f518fa659ef5e51cd89b495394699978dfe`. The container example now uses the `1.9.0` image, as the [README](https://github.com/ChefTaco/HiveMem/blob/v1.9.0/README.md) at that tag does, with the same `hive-qdrant:1.18.3-3` image and `issue-token` example; it was not re-run with the new image. The `rename-agent` paragraph above follows the [changelog](https://github.com/ChefTaco/HiveMem/blob/v1.9.0/CHANGELOG.md) and the [server README](https://github.com/ChefTaco/HiveMem/blob/v1.9.0/ts-core/README.md#renaming-an-agent); 1.9.0 also has `scripts/refresh_admin_token.mjs` mint its admin token for the subject `emberpath` instead of the retired `hive-router`. Per Hive's [UPGRADING](https://github.com/ChefTaco/hive/blob/v3.12.0/UPGRADING.md#suite-3120-cindertrace-080-and-the-emberpath-memory-principal), an upgrade to Hive 3.12.0 needs `--allow-migrations` only where `hive-router` owns HiveMem data. No installation command was run for this update.
