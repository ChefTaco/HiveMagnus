# Emberpath guide: earlier release records

These dated records were moved verbatim out of [`public/guides/emberpath.md`](../../public/guides/emberpath.md) so that the published guide keeps only its current release record. They describe the guide as it was on each date: "above" and "below" refer to that version of the guide, and the versions they name are not current. For current instructions read the [published guide](https://hivemagnus.com/guides/emberpath.md); for what each release changed, read the Emberpath [changelog](https://github.com/ChefTaco/Emberpath/blob/main/CHANGELOG.md).

Release update, 2026-11-12: [Hive 3.3.0](https://github.com/ChefTaco/hive/releases/tag/v3.3.0) pins Emberpath 2.1.0, tag [`v2.1.0`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.1.0), commit `08dc5f683203c80fb0b3d11d06495024e1fce417`. Per its [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.1.0/CHANGELOG.md), it verifies Oathweave admin tokens with the suite's shared verifier while keeping Emberpath's rules and the existing account link format, returns the suite-standard body from `/health/live` and `/health/ready` on both listeners, and tags every request with a request ID. The administration listener accepts a safe inbound request ID; the inference listener always generates its own. The standalone container example above keeps its original 2.0.1 review.

Release update, 2026-11-13: [Hive 3.7.0](https://github.com/ChefTaco/hive/releases/tag/v3.7.0) pins Emberpath 2.4.0, tag [`v2.4.0`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.4.0), commit `c87215750ab844ff526bdf61c35854dc2cec684e`. The container example now uses the `2.4.0` image, as the [README](https://github.com/ChefTaco/Emberpath/blob/v2.4.0/README.md) at that tag does; its environment file and commands are otherwise identical to the reviewed 2.0.1 example, and it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.4.0/CHANGELOG.md), 2.2.0 changes the data format (a suite upgrade from before Hive 3.4.0 needs `--allow-migrations`), 2.3.0 retires the bundled web UI, and 2.4.0 adds the Decisions API at `POST /v1/decisions`, which stays off until an operator enables a provider for it.

Release update, 2026-11-14: [Hive 3.8.0](https://github.com/ChefTaco/hive/releases/tag/v3.8.0) pins Emberpath 2.5.0, tag [`v2.5.0`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.5.0), commit `b9c7568c4af0d2a687774b2ade2cf5eb3046677a`. The container example now uses the `2.5.0` image, as the [README](https://github.com/ChefTaco/Emberpath/blob/v2.5.0/README.md) at that tag does; its environment file and commands are otherwise unchanged, and it was not re-run with the new image. The provider rules above follow the README's editing section and the [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.5.0/CHANGELOG.md) at that tag. Per Hive's upgrade notes, 2.5.0 adds no migration.

Release update, 2026-11-15: [Hive 3.9.3](https://github.com/ChefTaco/hive/releases/tag/v3.9.3) pins Emberpath 2.5.1, tag [`v2.5.1`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.5.1), commit `ab0d68266c7e0fb17471eb668e63e367ee933b0e`. The container example now uses the `2.5.1` image, as the [README](https://github.com/ChefTaco/Emberpath/blob/v2.5.1/README.md) at that tag does; it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.5.1/CHANGELOG.md), 2.5.1 moves to `@hivemagnus/hive-common` 0.5.0 and has the shared verifier require the admin token's `roles` and `clientId` claims, so a token without them is refused as `invalid_claims` before the online session check; Emberpath's own behaviour is otherwise unchanged and it adds no migration.

Release update, 2026-11-17: [Hive 3.11.2](https://github.com/ChefTaco/hive/releases/tag/v3.11.2) pins Emberpath 2.5.2, tag [`v2.5.2`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.5.2), commit `60553429c38577ade5c4eea2e2f811ea078b2b6b`. The container example now uses the `2.5.2` image, as the [README](https://github.com/ChefTaco/Emberpath/blob/v2.5.2/README.md) at that tag does; its environment file and commands are otherwise unchanged, and it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.5.2/CHANGELOG.md), 2.5.2 removes the static security-export credential, which expired on 2026-09-30: `GET /api/security/events` accepts only the `security-exporter` Oathweave client token. `HIVE_ROUTER_SECURITY_EXPORT_STATIC_FALLBACK_ENABLED=true` is still refused at startup, and `HIVE_ROUTER_SECURITY_EXPORT_TOKEN_HASH` is ignored, so existing env files keep working. It adds no migration.

It adds no migration.

Release update, 2026-11-20: [Hive 3.12.9](https://github.com/ChefTaco/hive/releases/tag/v3.12.9), tag `v3.12.9`, commit `353eb340634ae2fe8d63ae97360f701b9acb2a7b`, pins Emberpath 2.5.4, tag [`v2.5.4`](https://github.com/ChefTaco/Emberpath/releases/tag/v2.5.4), commit `0b21001af2bd6b6265aee805b9b121d2cca7ffe7` (Hive 3.12.0 to 3.12.7 pinned 2.5.3). The container example now uses the `2.5.4` image, as the [README](https://github.com/ChefTaco/Emberpath/blob/v2.5.4/README.md) at that tag does; its environment file and commands are otherwise unchanged, and it was not re-run with the new image. Per the [changelog](https://github.com/ChefTaco/Emberpath/blob/v2.5.4/CHANGELOG.md), the image carries `effect` 3.22.1 instead of 3.20.0, forced with an npm `overrides` entry, removing CVE-2026-121707 (a ReDoS in `Schema.TemplateLiteral`); its only consumer is the Prisma CLI's configuration loader, which runs for migrations, not request handling. It has no migration and no setting changes. No installation command was run for this update.
